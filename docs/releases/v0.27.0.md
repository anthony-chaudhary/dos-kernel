**TL;DR** — A release dominated by the **subagent-lease** fixes: a child agent
working inside the file-tree its parent already leased used to be hard-DENIED at
the PreToolUse gate (it mints its own run-id, so the gate didn't see the
ancestor's lease). It no longer is — the gate resolves the lineage chain first.
The companion change lets children **report their structural refusals up the
chain** so a parent can fold them. Alongside: `dos top` now shows what the kernel
itself did out-of-band, the account-switcher lands as a public driver with a
`dos accounts` seam, and a new `provider_ledger` witness adds a THIRD_PARTY
evidence band. No breaking ABI change.

## `arbiter` — subagents stop false-denying their own in-lane edits (#188)

- **What changed** — a subagent editing a file inside its ancestor's active
  lease is admitted, not hard-DENIED.
  - *Why:* a child mints its own `CID_RUN_ID`, so the admission gate saw "an
    unleased writer touching a leased tree" and refused — even though the
    ancestor that holds the lease is the one that spawned it.
  - *How:* `src/dos/pretool_sensor.py` + `src/dos/run_id.py` resolve `lineage_ids`
    and treat an ancestor's self-lease as a contained write; mirrored in the Go
    fast-path (`go/internal/hook/`) for Py↔Go parity.

## `decisions` — children report refusals up the lineage chain (#189)

- **What changed** — a child's structural refusal is no longer lost at the
  subprocess boundary; it propagates to the root run and folds into
  `dos status --children`.
  - *Why:* a parent that only reads its child's return string can't see *why* the
    child refused — the typed reason was stranded in the child's WAL.
  - *How:* `src/dos/child_refusals.py` (`fold_child_refusals`) + WAL
    `enforce`/`refuse_entry` rows now carry `root_id`/`parent_id`
    (`src/dos/lane_journal.py`); `dos status --children` renders the fold.
- **Also (#19)** — RESUME_PROPOSED runs now surface in the operator queue
  (`src/dos/decisions.py`) and the `dos-supervise-loop` skill consumes them.

## `cli` — `dos top` surfaces the kernel's own background activity

- **What changed** — a BACKGROUND ACTIVITY panel folds the kernel's out-of-band
  actions (watchdog HALT, reaper SCAVENGE, RECONCILE, breaker ENFORCE) that were
  journaled but invisible.
  - *Why:* an operator watching `dos top` could see the lanes but not what the
    kernel *itself* had been doing to them.
  - *How:* a pure fold over the entries `snapshot()` already reads
    (`src/dos/dispatch_top.py`), 6h TTL, fail-soft.

## `drivers` / `witness` — the account-switcher and a new THIRD_PARTY band

- **`dos accounts`** — the seat-pool seam lands in the public kernel, backed by a
  vendored account-switcher *driver* (resolved by name, not a static import — it
  passes the no-driver litmus).
- **`provider_ledger`** — a new witness band (THIRD_PARTY, docs/261): an
  external-effect-versus-different-principal-ledger check that the content-diff
  band can't reach.

## `arbiter` — tree-disjointness soundness (#144)

- **What changed** — `norm_tree_prefix` now truncates a glob at `?` and `[` as
  well as `*`, closing a false-disjoint where two trees that actually overlap
  were judged safe to run concurrently.
  - *How:* `src/dos/_tree.py` + the Go mirror (`go/internal/hook/tree.go`) for
    parity.
